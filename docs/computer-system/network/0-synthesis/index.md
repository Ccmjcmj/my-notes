## 学习中的疑问
 
❓Q1：一个应用开启一个进程，一个进程又开启多个线程。一个 TCP 连接就是一个线程，一个 TCP 连接里可以发多个 http 请求，对吗？

>💡
>✅ **正确部分：一个应用开启一个进程，一个进程又开启多个线程。大体正确。**

>浏览器是多进程：浏览器主进程、渲染进程（每个标签页大多一个渲染进程）；一个进程内可以跑多个线程：JS 线程、渲染线程、网络线程、定时器线程等。

❌ **错误：一个 TCP 连接就是一个线程。**

> 最大误区：**TCP 连接 ≠ 线程**

>- TCP 连接：操作系统内核维护的一条通信管道（socket），属于内核的东西。
>- 线程：是应用程序的执行单元，属于用户程序。

>关系：线程只是负责操作这个 TCP 连接，不是 TCP 连接本身就是线程。

>✅ **正确：一个 TCP 连接里可以发多个 http 请求。**<br>
>这个是对的，就是 HTTP 持久连接（keep‑alive）一条 TCP 管道，不关闭，就可以连续发多次 http 请求，接收多次响应。
**但历史上有个坑：**<br>
>- **HTTP/1.0**：是非持久连接；
>- **HTTP/1.1 持久连接下，默认队头阻塞**：必须等上一个请求响应回来，才能发下一个；
>后来 HTTP/1.1 有 pipeline，浏览器基本不用；
>- **HTTP/2 才真正做到同一条 TCP 连接并发多个 http 请求（多路复用）**
